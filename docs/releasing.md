# 维护与发布规范

产品显示名称统一为 **SocioLibrary**。版本由独立的版本号字段、`vX.Y.Z` 标签及软件包文件名表示，不把“正式安装版”等说明写入应用名、窗口标题或快捷方式提示。

## 发行资源

GitHub Release 标题使用 `SocioLibrary`，手工上传的资源仅包含四个软件包：Windows 安装程序、Windows 完整免安装 ZIP、Mac arm64 ZIP、Mac x86_64 ZIP。软件包文件名保留版本、系统和架构，供更新器精确选择。

SHA-256 在构建与暂存阶段照常核对，并放入发行说明正文；校验文件只保留在 CI artifact，不作为 Release 附件。文档、截图、报告放入仓库。GitHub 自动生成的源码归档由平台管理。

## 发布前检查

1. 按 `packaging/constraints` 中上一轮验证过的对应平台解析安装依赖，并执行 `pip check`。
2. 检查 Python、界面脚本和待公开文件。打包后执行离线的微型 BERT 编码与向量检索，验证精简没有破坏推理能力；这些随机权重只用于合成检查，不代表真实模型质量。
3. 验证前一公开安装版覆盖升级、程序运行时保护、原目录继承、更新器交接和自动重开，以及真实原生窗口和重复启动。
4. Windows 精简只移除构建目录中的开发文件。覆盖升级对照文件哈希；已修改的文件保留。旧依赖元数据必须由其 RECORD 校验通过，不跟随链接，也不删除未记录文件。
5. Mac ZIP 在各自架构重新解压并核对签名完整性，启动服务和 Cocoa 窗口；临时签名与未公证的限制保持公开。
6. 在草稿中暂存四个软件包，核对 GitHub 记录的摘要与 CI 验证输出，再公开发布。中英文首页、下载链接及版本说明同步更新。

不把开发机的文库、PDF、密钥、真实研究记录或日志加入构建、仓库或公开附件。
